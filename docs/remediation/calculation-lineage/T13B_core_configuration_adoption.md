## 14. Calculation Identity integration

`CoreEffectiveConfiguration` retains only the immutable shared
`EffectiveConfigurationSnapshot`. `values` decodes a new native tree on every
access, so caller mutations cannot alter its hashes or later execution values.
Core JSON replay rejects representations that cannot round-trip without numeric
loss. No Settings object, mutable profile/config dict or absolute source file is
retained by the snapshot.

`bind_configuration` replaces the existing Phase-1 effective-configuration
dimension with T13A's complete `EffectiveConfigurationIdentity`: family,
schema and canonical semantic digest. Identity is completed when native exact
input/code/context lineage is available, using the already frozen configuration
that governed calculation. Producer version/context labels stay outside semantic
hashing; provenance hash also stays outside Calculation Identity.

With identical inputs/code/context, behavioral C1 -> C2 changes Calculation
Identity. Same behavior/different source keeps its configuration identity.
Combined/Ranking propagate upstream changes through exact source references and
upstream fingerprints, without duplicating upstream behavioral trees.

## 17. Retry/resume behavior

All four core entry points accept a frozen `effective_configuration`; the
all-profile entry accepts a tuple. An exact retry reuses the object or rehydrates
C1 from verified immutable evidence and executes its native values. A supplied
`expected_calculation_identity` rejects C2 against C1 before financial calculation
(`CORE_CONFIGURATION_RETRY_MISMATCH`). Existing input/code/context validation
continues separately; this guard checks the configuration dimension.

The native PG test attacks current entry resolvers so any accidental current
resolution fails. All four anchored retries reuse C1 identity and evidence ID,
with unchanged payloads. Supplying C2 creates a new calculation and evidence;
it cannot retain a supplied C1 anchor. An unanchored call intentionally resolves
current configuration and gets the corresponding new identity. Persisting and
delivering these anchors across durable job restart/resume is T13D; this report
does not claim a durable pipeline manifest or original-context replay protocol.
