# Bounded configuration calculation reuse

The required SLSE scale gate reaches the native writer after the fixture repairs.
A five-member profile located repeated configuration serialization/fingerprint
calculation in canonical selection and lifecycle authority checks. This change
reuses those pure calculations while retaining each caller's authority checks.

The bounded 64-entry cache key copies every standard snapshot field: family,
resolution and precedence, classified family keys, each entry's complete typed
value/provenance/default/override fields, producer version and evaluation time.
Boolean and integer fields retain their types. Cache keys contain immutable
primitive tuples/strings and code types; values contain only calculated hashes
and canonical strings. ORM rows, sessions, bindings and verdicts are not cached.
Nonstandard snapshot/family/entry/source shapes use the original uncached
constructor and serializer, including any extension metadata.

Each call still compares supplied semantic/resolution hashes and identity to
the calculated content, checks executable family requirements, resolves the
current database owner/binding and compares the complete retained canonical
configuration. Payload seals, financial/source-value comparisons, locks and
writer transaction fences remain unchanged. A changed field produces a different
calculation key; changed supplied cached properties are checked on every call.
No scoring formula, financial value, canonical hash format or tolerance changes.

All ten warm-cache controls pass: six content/declared-identity/provenance/type
attacks, three retained-metadata changes with equal semantic/resolution hashes,
and a changing nonstandard extension. The binding control confirms that every
call still resolves the owner, including after warming the calculation cache.
These are FAST/UNIT_DOUBLES controls. Native PostgreSQL delivery, source-boundary,
writer fault, lock and rollback regressions are run separately.

Native reconstruction also reuses type hints only inside one reconstruction
call. Repeated signal definitions are reconstructed as one list, retaining the
original raw registry keys and member order. Each call resolves live schemas
again and creates fresh native objects; no type-hint result survives the call.
A further control changes a nested enum annotation between calls and checks
both the changed type and independent outputs. All 72 final contextual/decision
reconstruction and cache controls pass. The 116 core/decision/native delivery,
source-boundary, cache-authority, writer-fault and rollback regressions passed
with calculation reuse. Current-source CI must execute the final source again.

The same five-member diagnostic profile observed about 34.4 seconds before and
9.2 seconds after calculation reuse. This includes profiling overhead and does
not certify the original 1,000-ticker budget. The complete scale gate, unchanged
source-bound CI and current A04 financial comparisons remain required. The
historical CERI certificate/archive retains its original source and bytes.
